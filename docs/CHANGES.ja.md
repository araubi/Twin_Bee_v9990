# ツインビー V9990：変更点と技術的な詳細

## 構成

### SCC版（ベース：Twin Bee SCC Enhanced、128KB → 256KB、Konami SCCマッパー）

| 8KBバンク | 内容 |
| --- | --- |
| 0 | SCC版の起動処理。V9990ローダーへのジャンプを追加。 |
| 1-3 | SCCサウンドドライバと音楽。 |
| 4 | V9990ローダーとドライバ。末尾に `sndfast`（PSG/SCCへの高速出力）。ドライバはRAMのD520h以降に、変数はC000hに置かれます。どちらもSCC版が使わない領域です（SCC版はC800h-C9FFh、D000h-D2FFh、D506h-D507h、D514hを使用）。 |
| 5-8 | ゲーム本体。小さなパッチを適用：割り込みフック、TMS9918への書き込み、地上物の登録、自機の下限（1Pと2P）、画面下に出た敵と弾を消す位置、フォントローダー（Xの文字用）、クレジットのテーブル。 |
| 9-31 | V9990用グラフィック（タイル、マップ、スプライト、パレット）を圧縮して格納。 |

### PSG版（ベース：オリジナル版ツインビー、32KB → 256KB、Konamiマッパー）

| 8KBバンク | 内容 |
| --- | --- |
| 0-3 | 同じ小さなパッチを当てたオリジナルのゲーム。INITから4010hのスタブに飛び、バンク4を設定します。 |
| 4 | V9990ローダーとドライバ。ドライバはRAMのC800hに、変数はC000hに置かれます。`slotfix`（40D1h）がバンクとH.KEYIフックを設定します。 |
| 5-31 | V9990用グラフィック。容量に余裕があるため全てRLEで、読み込みも速くなっています。 |

### V9990ドライバ

- P1モード、256x212、2レイヤー：B =「mapa N - paleta 1」、A =「mapa N - paleta 2」。64x64タイルのマップを64行のリングバッファに格納（Aは7C000h、Bは7E000h）。
- **ライン割り込み（191ライン）：** 次のフレームのスクロール値の上位を書き込みます。
- **垂直割り込み：**
  1. まずスクロール値の下位を、画面の描画が始まる前に書き込みます（ソニー HB-F900などの実機では必須）。
  2. SCC音楽の1ステップ（SCC版のみ）。
  3. マップとスプライト。
  4. ゲームの割り込み処理へジャンプ。
- TMS9918の割り込みも受け付け、BIOSがキーボードと時計の処理を実行しないようにしています。
- **スプライト：** MSXの各スプライト（パターンと色）を、1枚以上の16色スプライトに変換します。コンテキスト（ステージとボス）ごとの対応表は `src/sprites.py`（`COMMON` と `SPECIFIC`）にあります。データはV9990に送る順に、256バイトのページ単位で格納されています。
- **MSX側の画面：** プレイ中はポーズウィンドウ（ステージ、ハイスコア、スコア、残機）を表示し、毎秒約7回更新します。デモ中は黒のままです。

## テスト期間中の変更

### グラフィックとスプライト

- ベル：黒いベル（取るとミスになるもの）に絵がなく黄色に見えていたため、専用の絵を用意しました。ステージ3では緑のベルが黒いベルの絵になっていたのを修正。
- 白く表示されていた物体：キャンディ、ステージ3の星、ステージ4の手に絵を付けました。壺はスプライトシートの絵を使用。
- 自機のミス（オリジナルROMで確認）：MSXでは真っ白な自機と墜落した自機が交互に表示されます。白いフレームでバリア付きの自機が表示されていたのを、自機そのものの白いシルエットに修正（ウインビーも同様）。
- 被弾時：新しいアートではしぶきと小さなハチがどちらも白で、重なって見えていました。しぶきを先に、その後ハチを表示するようにしました（`driver.asm` の `SPL_HALF`）。
- 特定のステージ用に描き直されたスプライト（例：ステージ2の赤いベル）がステージ1から取られていました。常にそのステージの絵を使うように修正。
- 爆弾投下時、被弾時、サイレン時に自機が消えなくなりました（傾いた自機の絵が抜けていました）。
- 敵弾を最前面に：敵弾はゲームのスプライトテーブルの25-31番に入っており、ドライバはそれを最初にV9990へ送ります。V9990は先頭のスプライトを手前に描くため、雲や敵に隠れず、1ライン16枚の制限で消えることもなくなりました。
- クレジット：新しい行 **COLOR GUANTXIP** を追加。ゲームにはXの文字がなかったため、他の文字と同じく文字の1-7行目を使ってフォントに追加しました。

### 画面とスクロール

- **画面全体のちらつき。** 原因は2つありました。
  - 192ラインでの区切りを画面オフ（R#8）で行っていましたが、このビットは各フレームの開始時にしか読まれないため、割り込みが遅れると1フレームまるごと失われていました。現在は区切りをなくし、下の20ラインもゲーム画面になっています（自機の下限はC300h、敵と弾はY = D4hから消去）。
  - TMS9918の割り込みでBIOSの処理が走り、V9990の割り込みが最大1.5ms遅れていました。現在はドライバがこれを無効にしています。
- ステージ開始時、ポーズ解除時、ステージ切り替え時は、リングバッファの見えていない半分に4フレームかけてマップを描き直し、完成した時点で一度に切り替えます。
- スクロール停止中（ボス戦）：ゲームが進んでいないのに細かいスクロール量が増え続け、背景が前後に揺れていました（「ムーンウォーク」）。現在は最後の実際のスクロールから計算しています。スクロール停止中に約4秒ごとに背景がずれる問題も修正。
- **HB-F900で画面が揺れる問題：** あるテスト版では音楽処理をスクロールより先に行っていたため、スクロール値の下位が割り込みから約3ms後、描画開始後に書き込まれていました。現在は約0.3msで書き込み、その直後に音楽処理を行います。
- ロゴとメニュー：ドライバが毎フレームMSXの画面全体をコピーしていました。現在は1フレームあたり最大64文字のコピーとし、SCC版と同じ速度で動きます。

### ボス

- ボス出現時にマップが次のステージのものに切り替わっていました（ボス5では存在しないマップに）。現在は各ステージのマップの最後でボスと戦います。
- 各ボスの島の画面はアート上で2回（あるマップの最後と次のマップの最初）、違いのある絵と異なるパレットで描かれており、ボスを倒すとタイルや色が変わって見えていました（DTensoMSXさんの報告）。変換ツールが両方の場所に同じ絵を、両ステージ共通の色で置くようにし、ボスごとに色の損失が最も少ない絵を選びます（ボス2の灯台、ボス1の茶色の岩）。
- 島の画面の下には、マップにある海岸の帯をそのまま残し、次のマップにも置くようにしました（以前は海に置き換えており、ボス出現直前のちらつきに見えていました。Xavi Sorinasさんの報告）。
- ボス画面の上の行：変換ツールが各マップの最終行の後に、次のマップの島の画面の上にある行を追加します。これによりボス戦中も撃破後も同じ表示になります（ボス5の二重の波、右上の崖）。
- 上から登場するボスはY = D1hから始まり、倒されるとゲームはそのスプライトをY = D0hに退避させます。MSXでは表示されませんが、V9990は20ライン多いため見えていました。現在はYがD0h-DFhのスプライトは描画しません。
- ボス5撃破時：ゲームはスクロール位置を1760から26に戻し、背景が5ライン下がっていました（「ダンス」）。現在はこのようなジャンプでは背景を動かしません。
- ステージ4のアート：「mapa - paleta 2」では最後の島の画面の崖が「paleta 1」より1行上にありました。変換ツールで補正しています。
- ボス戦でミスした後の音楽：ステージの音楽が流れます。これはオリジナルのゲームの仕様です（GFX9000なしのSCC版も同じ）。

### SCC音楽

- 曲の開始時にチャンネルが抜ける問題（Xavi Sorinasさんの報告）：SCCプレーヤーは割り込み許可状態で自分のバンクを設定して動作しており、その最中にV9990の割り込みが来ると、ドライバがゲームのバンクに戻していました。現在は：
  - 音楽の1ステップを各フレームの最初、スクロール書き込みの直後に行います。
  - 割り込みがプレーヤーの実行中に来た場合、ドライバは何も変更しません。
  - 描き直しを複数フレームに分け、音楽を遅らせないようにしました。
  30秒のプレイで音楽は1798ステップ進み、GFX9000なしのSCC版と同じです。
- ポーズ中の音：オリジナルのSCC版もポーズ中にPSGとSCCへまったく同じ書き込みを行っています。

### 処理速度（SCC版）

openMSXでの全編プレイ、ゲームロジックの毎秒フレーム数：

| | 以前 | 現在 | GFX9000なしのSCC版 | オリジナル（PSG） |
| --- | --- | --- | --- | --- |
| ステージ1-5 | 25.6-27.0 | 28.9-30.0 | 26.2-27.2 | 29.9-30.7 |
| ボス1と4 | 20.5-21.3 | 24.7-25.9 | 21.4-21.7 | 30.0 |
| ボス2、3、5 | 24.9-26.5 | 28.8-29.5 | 23.8-25.6 | 30.0 |
| **合計** | **25.0** | **28.6** | **25.3** | **30.0** |

- **SCCプレーヤー：** 1ステップあたり3.1msから2.0msに短縮。PSGとSCCへの出力を書き直しました（`src/sndfast.asm`）。BIOS（WRTPSG）を呼ばずにPSGのポートへ直接書き込み、SCCのウィンドウを開くのも1回だけにしています。書き込み内容は以前とまったく同じで、レジスタ単位で確認済みです。
- **スプライト：** ロジック1フレームあたり5.3msから3.9msに短縮。空のエントリを早めにスキップし、データを送信順に並べています。
- PSG版はオリジナルと同じ30.0で動作します。

### 圧縮

- グラフィックは展開の速いRLEで格納し、SCC版で容量に収めるためにより強い圧縮（LZ）が必要なブロックのみLZを使っています（42ブロック中12）。起動時の読み込みは約2.2秒です。
